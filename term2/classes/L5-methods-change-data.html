Methods can change attributes

Until now methods just printed. But a method can also CHANGE the object's own data. Watch a method add to the score:

✅ The score goes up and STAYS up
class Player: def __init__(self): self.score = 0 def add_point(self): self.score = self.score + 1 # change the object's own data p = Player() p.add_point() p.add_point() print(p.score) # 2

Each p.add_point() raises the score by 1. And here's the key thing: the object remembers. After two calls, the score is 2 and stays 2. The data lives on, change after change.

The shortcut: += and -=

self.score = self.score + 1 is so common there's a shortcut:

self.score += 1 # same as self.score = self.score + 1 self.health -= 10 # same as self.health = self.health - 10

+= means "add to". -= means "take away from". You'll use these constantly for score and health.

A health example

class Player: def __init__(self): self.health = 100 def take_damage(self, amount): self.health -= amount p = Player() p.take_damage(30) p.take_damage(20) print(p.health) # 50

100, then take 30 → 70, then take 20 → 50. The method changes self.health each time, and the object holds onto the latest value.

Stopping a value going too far (a real game trick)

A pet game in our class needed hunger to never go above 100 or below 0. The clean way uses min() and max():

def feed(self): self.hunger = min(100, self.hunger + 10) # never above 100 def wait(self): self.hunger = max(0, self.hunger - 5) # never below 0

min(100, x) = the smaller of 100 and x → caps the top. max(0, x) = the bigger of 0 and x → caps the bottom. Two tiny tools that stop bugs.
