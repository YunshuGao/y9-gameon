👥 Lesson 6 — Many objects from one class

The big payoff: build a whole army of objects from one class, keep them in a list, and loop over them.

📖 These are your STUDY NOTES — read them at your own pace. This is the full explanation with lots of examples. You don't have to memorise it — keep it open in another tab while you do the worksheet. When you're ready to practise, go back to the worksheet.

One class → many objects in a list

You've built objects one at a time. Now build a whole bunch and store them in a LIST:

✅ A list of objects
class Enemy:
    def __init__(self, name, health):
        self.name = name
        self.health = health

# a list of THREE enemy objects:
enemies = [
    Enemy("Goblin", 30),
    Enemy("Orc", 50),
    Enemy("Troll", 80),
]

enemies is a normal list — but each item is a whole Enemy object, with its own name and health.

Looping over the objects

Loop over the list and reach into each object's data with the dot:

for enemy in enemies:
    print(enemy.name, "has", enemy.health, "health")

# Goblin has 30 health
# Orc has 50 health
# Troll has 80 health

Each time round the loop, enemy is the next object in the list. enemy.name and enemy.health reach into THAT enemy's data.

Calling a method on every object

If the class has a method, you can call it on every object in the loop:

class Enemy:
    def __init__(self, name):
        self.name = name
    def roar(self):
        print(self.name + " roars!")

enemies = [Enemy("Goblin"), Enemy("Orc")]
for enemy in enemies:
    enemy.roar()        # each enemy roars

# Goblin roars!
# Orc roars!

Why this is the whole point of classes

  • Want 5 enemies? Add 5 to the list. Want 50? The loop doesn't change.
  • Each object remembers its OWN data — Goblin's health is separate from Orc's.
  • One method (roar) works for every object.
  • This is exactly how games spawn waves of enemies, bullets, coins, stars...

Class (blueprint) + list (many objects) + loop (do something to each) = a game system. You now have all three pieces.
