🏗️ Lesson 8 — Build your own class (capstone)

Everything you've learned, put together into ONE class you design and build — step by step, with scaffolding.

📖 These are your STUDY NOTES — read them at your own pace. This is the full explanation with lots of examples. You don't have to memorise it — keep it open in another tab while you do the worksheet. When you're ready to practise, go back to the worksheet.

The 7 things you now know

1. CLASS    — the blueprint:           class Pet:
2. __init__ — the setup method:        def __init__(self):
3. self     — this object:             self.name
4. PARAMS   — values coming in:        def __init__(self, name):
5. ATTRIBUTE— data the object has:     self.health = 100
6. METHOD   — an action it does:       def feed(self):
7. CHANGE   — a method edits data:     self.hunger += 10

Build along: a complete Pet class, one piece at a time

We'll build a full virtual pet together. Each step adds ONE thing you already know. Follow along, then the tasks ask you to build your OWN.

Step 1 — the blueprint and setup:

class Pet:
    def __init__(self, name):
        self.name = name
        self.hunger = 50
        self.happiness = 50

Step 2 — add a method that changes data (with capping):

    def feed(self):
        self.hunger = min(100, self.hunger + 20)
        print(self.name + " has been fed. Hunger: " + str(self.hunger))

Step 3 — add another method:

    def play(self):
        self.happiness = min(100, self.happiness + 15)
        print(self.name + " played. Happiness: " + str(self.happiness))

Step 4 — build the object and use it:

my_pet = Pet("Mochi")
my_pet.feed()
my_pet.play()
print(my_pet.hunger, my_pet.happiness)

That's a complete program made of one class!

Blueprint + attributes + methods + changing data — everything from Lessons 1-5. The capstone tasks below ask you to build your own version. Take it step by step, just like this. Run it after each step to check it works.

How to build without getting stuck

  • Write the class line and __init__ first. Run it. No errors? Good.
  • Add ONE method. Run it. Test it.
  • Add the next method. Run it.
  • Never write the whole thing then run — add one piece at a time.
  • Stuck? Look back at the build-along above, or ask Ms Gao.
