🎚️ Lesson 3 — Objects that are DIFFERENT

Right now every object starts the same. Today: pass in values so each object can be different — Dog("Rex") vs Dog("Bella").

📖 These are your STUDY NOTES — read them at your own pace. This is the full explanation with lots of examples. You don't have to memorise it — keep it open in another tab while you do the worksheet. When you're ready to practise, go back to the worksheet.

The problem: every object is identical

❌ Every dog is the same
class Dog:
    def __init__(self):
        self.name = "Rex"     # EVERY dog is Rex!

a = Dog()
b = Dog()
print(a.name, b.name)    # Rex Rex  :(

The fix: a PARAMETER in __init__

Add a parameter (an input) to __init__ after self. Then the name comes from OUTSIDE when you build the object:

✅ Each dog is different
class Dog:
    def __init__(self, name):     # name comes IN
        self.name = name          # store the value we were given

a = Dog("Rex")
b = Dog("Bella")
print(a.name, b.name)    # Rex Bella  :)

Reading it carefully

  • def __init__(self, name): — self first (always), then name is a value coming in.
  • self.name = name — store the incoming name onto the object as self.name.
  • Dog("Rex") — the "Rex" goes IN as name. This dog's name becomes Rex.
  • Dog("Bella") — a different dog, name Bella. Same blueprint, different data.

Passing in MORE than one value

class Enemy:
    def __init__(self, name, health):
        self.name = name
        self.health = health

goblin = Enemy("Goblin", 30)
orc = Enemy("Orc", 50)
print(goblin.health)   # 30
print(orc.health)      # 50

List the parameters in order after self. When you build, pass the values in the SAME order: Enemy("Goblin", 30) → name="Goblin", health=30.

The golden rule

self.name = name is the most common line in all of classes. "Store the value I was given onto this object." You'll write it hundreds of times. Practise it until it's automatic.
