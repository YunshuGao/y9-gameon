The problem inheritance solves

Imagine four enemy types. They all have name, health, damage, and a take_damage method. Only their ATTACK differs. Without inheritance you'd copy the shared code into all four classes — pure DRY violation (Lesson 2!).

Parent class — the shared stuff, written ONCE

✅ Parent: shared behaviour, once
class Enemy: # PARENT def __init__(self, name, health, damage): self.name = name self.health = health self.damage = damage def take_damage(self, amount): self.health -= amount def attack(self, target): target.health -= self.damage

Child classes — inherit everything, change only what's different

✅ Children: only the differences
class Zombie(Enemy): # CHILD — inherits from Enemy def __init__(self): super().__init__("Zombie", 40, 8) # call parent setup class Skeleton(Enemy): # another CHILD def __init__(self): super().__init__("Skeleton", 25, 5) def attack(self, target): # OVERRIDE — skeletons attack differently target.health -= self.damage * 2 # double damage! print(f"{self.name} fires an arrow!")

The three magic words

  • class Zombie(Enemy): — the (Enemy) means 'Zombie inherits from Enemy'. Zombie gets take_damage and attack for free.
  • super().__init__(...) — calls the PARENT's setup, so you don't re-type self.name = name etc.
  • Overriding — if a child defines a method the parent already has (like Skeleton's attack), the child's version wins for that child.

Why this is the big one

Zombie() and Skeleton() both have take_damage() — written ONCE in the parent. Want a Dragon? class Dragon(Enemy): and only write what's special. Shared code lives in one place; differences live in the children. This is exactly how the ghosts worked: one Ghost parent, four children that only changed choose_move.

# all four ghosts share the parent Ghost class. # each child only overrides how it chooses where to move: class Blinky(Ghost): def choose_move(self, player): return chase_directly(self, player) class Clyde(Ghost): def choose_move(self, player): return move_randomly(self)
