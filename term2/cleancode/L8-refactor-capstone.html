How to refactor without breaking your game

  • Make a copy first. Save mygame_v2.py so your working version is safe.
  • Change ONE thing, then run it. Fix input validation → run → still works? Good. Next item.
  • Never change five things then run. If it breaks you won't know which change did it.
  • Test the edges. Type a letter at a number prompt. Enter blank. Type a huge number. Your game should survive all of it now.

What 'good' looks like

Here's the difference one refactor pass makes, using a real before/after shape from our class:

❌ Before
# BEFORE: global, repeated, crashes on bad input score = 0 ans = int(input("Q1? ")) # crashes on text if ans == 4: score = score + 1 ans = int(input("Q2? ")) # same line, pasted if ans == 9: score = score + 1
✅ After — every lesson applied
# AFTER: a function, a data structure, validated input def ask(question, answer): while True: t = input(question + " ") if t.isdigit(): return int(t) == answer print("Numbers only.") quiz = [{"q": "Q1?", "a": 4}, {"q": "Q2?", "a": 9}] score = sum(1 for item in quiz if ask(item["q"], item["a"]))
