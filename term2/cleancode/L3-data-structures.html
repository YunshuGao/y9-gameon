The parallel-list trap

Here's a real quiz from our class. The questions are in one list, the answers in another:

❌ Two lists kept in sync by position
questions = ["Capital of Australia?", "How many continents?", "12 x 12?"] answers = ["canberra", "7", "144"] for i in range(len(questions)): user = input(questions[i]).lower() if user == answers[i]: # matched by POSITION — fragile! score += 1

This works... until you insert a new question at the start of questions but forget to insert its answer at the start of answers. Now every question is paired with the WRONG answer and the whole quiz is broken. Nothing crashes — it's just silently wrong.

Fix — group each question WITH its answer (a dictionary)

A dictionary stores data as key: value pairs. Keep each question glued to its own answer:

✅ A list of dictionaries
quiz = [ {"question": "Capital of Australia?", "answer": "canberra"}, {"question": "How many continents?", "answer": "7"}, {"question": "12 x 12?", "answer": "144"}, ] for item in quiz: user = input(item["question"]).lower() if user == item["answer"]: # answer can NEVER drift from its question score += 1

Now each question and its answer live in the same little box. Move a question, and its answer moves with it. They can't fall out of sync.

List vs Dictionary — when to use which

  • List [ ] — an ordered line-up of things you reach by POSITION: scores[0], players[2].
  • Dictionary { } — labelled boxes you reach by NAME (key): item["answer"], player["health"].
  • List of dictionaries — the power combo: many records, each with named fields. Perfect for quiz questions, enemies, inventory items.

Why this matters for classes (next week)

A dictionary like {"name": "Goblin", "health": 40} is one step away from a class. A CLASS is just a dictionary that also carries its own behaviour (methods). Master grouping data now, and classes will feel natural.
