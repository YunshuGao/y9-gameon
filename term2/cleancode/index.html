🐍 Y9 Game On · Term 2
Overview🎮 Arcade

🧹 Clean Code → Classes

You've all built working games — now let's make your code GREAT. These 8 lessons take the real skills from your submitted games and level them up: writing code that doesn't crash, that doesn't repeat itself, and that's organised into clean classes. By the end you'll be ready for the big classes work in Term 3. Every lesson uses real code from our class (names removed) so you can see exactly what to improve.
🛡️

Lesson 1 — Defensive Input: never trust the user

Lesson 1 · 55 min · /33 marks

When Ms Gao marked your games, 13 out of 16 CRASHED the moment she typed a letter where a number was expected. Your game logic is great — but one bad keypress kills it. Today we make your programs bulletproof.
♻️

Lesson 2 — DRY: Don't Repeat Yourself

Lesson 2 · 55 min · /35 marks

Several games in our class had the SAME 8 lines of code copy-pasted two or three times (the easy quiz and the hard quiz; the game and the 'play again' game). When you copy-paste, every fix has to be made in every copy. Today: one function, called many times.
🗂️

Lesson 3 — The Right Data Structure: lists vs dictionaries

Lesson 3 · 55 min · /35 marks

Lots of our quiz games kept questions in one list and answers in a SEPARATE list, matched by position. Add one question in the wrong spot and every answer is suddenly wrong. Today: how to GROUP related data so it can't fall out of sync. This is the exact thinking you'll need for classes next.
📦

Lesson 4 — Why a Class? From globals to objects

Lesson 4 · 60 min · /35 marks

One of the most ambitious games in our class used global coins, global inventory, global player all over the place — while ANOTHER game kept everything tidy in a player object. Today you'll feel the difference, and write your first class to hold related data together.
🔧

Lesson 5 — Attributes & Methods: the inside of an object

Lesson 5 · 60 min · /36 marks

You can make a class now (Lesson 4). Today we go deeper: passing values into __init__, the difference between attributes and methods, and a real trick from a pet game in our class — keeping a stat between 0 and 100 with min() and max().
⚔️

Lesson 6 — Objects Interacting: hero.attack(goblin)

Lesson 6 · 60 min · /38 marks

Several of your Path B games had heroes fighting goblins. The magic that makes combat work is a method that takes ANOTHER object as a parameter and changes it: hero.attack(goblin) reduces the goblin's health. Master this and you can build any interactive system.
🧬

Lesson 7 — Inheritance: parent and child classes

Lesson 7 · 60 min · /37 marks

The most advanced game in our class had FOUR ghost types — Blinky, Pinky, Inky, Clyde — that shared most of their code but each chased the player differently. The student didn't copy-paste four times. They used INHERITANCE: a parent Ghost class, and four children that only changed what was different. This is the most powerful idea in classes, and the heart of Term 3.
🏆

Lesson 8 — Refactor Your Own Game (capstone)

Lesson 8 · 70 min · /40 marks

You've learned to validate input, kill duplication, group data, build classes, make objects interact, and use inheritance. Today you put it ALL together — on your own game. By the end you'll have a cleaner version of your project AND the exact mindset you need for the big classes work in Term 3.
