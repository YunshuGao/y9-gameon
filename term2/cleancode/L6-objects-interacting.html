A method that touches another object

Up to now, methods changed their OWN object (self.health). Now the leap: a method takes another object as a parameter and changes IT.

✅ The combat pattern from our class
class Character: def __init__(self, name, health, damage): self.name = name self.health = health self.damage = damage def attack(self, target): # target is ANOTHER Character target.health -= self.damage # change the OTHER object print(f"{self.name} hits {target.name} for {self.damage}!") hero = Character("Hero", 100, 12) goblin = Character("Goblin", 30, 4) hero.attack(goblin) # hero is self, goblin is target print(goblin.health) # 18

Reading hero.attack(goblin)

  • hero becomes self (the attacker).
  • goblin becomes target (the one being hit).
  • target.health -= self.damage = 'reduce the goblin's health by the hero's damage'.
  • Two different objects, one method, talking to each other. That's a game system.

A list of enemies + a loop = a battle

Now combine with Lesson 3 (lists of objects) and Lesson 1 (loops). The hero attacks every goblin in a list:

goblins = [Character("Grub", 20, 3), Character("Snik", 15, 4), Character("Murk", 25, 5)] for goblin in goblins: hero.attack(goblin) # hero hits each one in turn

The full turn-based loop

Hero hits a goblin; if it survives, it hits back. Keep going while both are alive:

while hero.health > 0 and goblin.health > 0: hero.attack(goblin) if goblin.health > 0: # only hits back if still alive goblin.attack(hero) if hero.health > 0: print("Hero wins!") else: print("Hero falls...")

Every fighting game you submitted is built on exactly this shape. Once two objects can change each other, everything else is detail.
